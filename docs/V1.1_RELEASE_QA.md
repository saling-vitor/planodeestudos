# Plano ARQ · Release QA V1.1.0

O CI já cobre DPR/escala, múltiplas viewports, 84 casos de mapas, Data Safety e cold-offline. O Chrome headless, porém, não reproduz de forma confiável o **zoom real do navegador**.

Por isso, antes de promover a V1.1.0, é obrigatório validar manualmente no Chrome real:

- **80%**
- **125%**
- **150%**

## Páginas mínimas

Em cada nível de zoom:

1. abrir `biblioteca.html`;
2. abrir `configuracoes.html`;
3. abrir um mapa real pela Biblioteca.

## Aceite

Em cada página verificar:

- nenhuma rolagem horizontal global inesperada;
- nenhum botão, card, modal ou menu cortado;
- topbar e navegação sem colisões;
- texto e controles legíveis;
- busca, Mais, abrir/recolher tópico e navegação continuam acessíveis.

## Como registrar

O estado é mantido em `data/release-qa-v11.json`.

Após executar cada teste manual, mudar apenas o item correspondente para:

```json
{
  "status": "approved",
  "checkedAt": "AAAA-MM-DDTHH:MM:SS-03:00",
  "evidence": "descrição curta do dispositivo/navegador testado"
}
```

O comando:

`python3 scripts/validate_release_qa.py --release`

**deve falhar** enquanto qualquer item obrigatório estiver pendente. O workflow de desenvolvimento verifica somente a estrutura do checklist; o gate de promoção usará o modo `--release`.
