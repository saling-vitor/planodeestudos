# Plano ARQ · Release QA V1.1.0

O CI já cobre DPR/escala, múltiplas viewports, 84 casos de mapas, Data Safety e cold-offline. O Chrome headless, porém, não reproduz de forma confiável o **zoom real do navegador**.

Por isso, antes de promover a V1.1.0, é obrigatório validar manualmente no Chrome real:

- **80%**
- **125%**
- **150%**

## Páginas mínimas

Em cada nível de zoom:

1. abrir `biblioteca.html`;
2. abrir `configuracoes.html`;
3. abrir um mapa real pela Biblioteca.

## Aceite

Em cada página verificar:

- nenhuma rolagem horizontal global inesperada;
- nenhum botão, card, modal ou menu cortado;
- topbar e navegação sem colisões;
- texto e controles legíveis;
- busca, Mais, abrir/recolher tópico e navegação continuam acessíveis.

## Como registrar

O estado é mantido em `data/release-qa-v11.json`.

Após executar cada teste manual, mudar apenas o item correspondente para:

```json
{
  "status": "approved",
  "checkedAt": "AAAA-MM-DDTHH:MM:SS-03:00",
  "evidence": "descrição curta do dispositivo/navegador testado"
}
```

O comando:

`python3 scripts/validate_release_qa.py --release`

**deve falhar** enquanto qualquer item obrigatório estiver pendente. O workflow de desenvolvimento verifica somente a estrutura do checklist; o gate de promoção usará o modo `--release`.


## Gate final

O workflow **Gate V1.1 Release** (`.github/workflows/release-gate-v11.yml`) é o gate de promoção.

Ele executa:

- validadores de produção, layout, CSS, JavaScript, PWA e versões;
- `validate_release_qa.py --release`;
- Data Safety;
- 84 casos dos mapas;
- cold-offline;
- auditoria visual completa do Portal.

Enquanto qualquer zoom obrigatório estiver com `status: "pending"`, o workflow deve falhar antes da regressão de navegador. Isso é intencional.


## Gate do Release Candidate

O workflow **Gate V1.1 RC** (`.github/workflows/rc-gate-v11.yml`) roda automaticamente em branches `release/v1.1.0-rc*`.

Ele aceita os três testes de zoom como `pending`, porque a função do RC é justamente fornecer uma base congelada para esse QA manual.

Além da regressão completa, ele executa `validate_release_candidate.py --git`, que compara o HEAD com o `functionalFreezeSha` e reprova qualquer mudança pós-freeze fora da allowlist.

O **Gate V1.1 Release** permanece mais restritivo: além do freeze, exige `validate_release_qa.py --release`, portanto não pode ficar verde enquanto 80%, 125% e 150% não forem aprovados.
