# Plano ARQ · Release QA V1.2.0

O CI cobre regressão de dados, mapas, Portal, PWA, offline, JavaScript, CSS e contratos de release. O **zoom real do navegador** continua sendo um teste manual.

## Checks obrigatórios

No Chrome real:

- **80%**
- **125%**
- **150%**

## Escopo mínimo

Em cada zoom:

1. abrir `biblioteca.html`;
2. abrir `configuracoes.html`;
3. abrir um mapa real pela Biblioteca.

## Aceite

- nenhuma rolagem horizontal global inesperada;
- nenhum botão, card, modal ou menu cortado;
- topbar e navegação sem colisões;
- texto e controles legíveis;
- interações principais acessíveis;
- contexto/troca de concurso preservado.

## Registro

O estado fica em `data/release-qa-v12.json`.

Durante o RC, os três itens podem permanecer `pending`.

`python3 scripts/validate_release_qa_v12.py`

aceita pendências e valida a estrutura.

Para a promoção final:

`python3 scripts/validate_release_qa_v12.py --release`

deve falhar até 80%, 125% e 150% estarem `approved` com data e evidência.

## Gate RC

O workflow **Gate V1.2 RC** roda em `release/v1.2.0-rc*` e valida estrutura, layout, CSS, JavaScript, PWA/cache, freeze, candidato, QA, Data Safety, mapas, offline, Portal e fluxo de concurso novo.

A versão pública permanece **1.1.0** durante o RC.

## Gate final

O futuro **Gate V1.2 Release** exigirá `validate_release_qa_v12.py --release`.
