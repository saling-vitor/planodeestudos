## Estado inicial

A branch V1.2 foi aberta **sem funcionalidade nova**.

Ainda não estão autorizados:

- bump da versão de produto para 1.2.0;
- redesign;
- migração de storage;
- remoção de aliases/compatibilidade;
- alterações de mapas, PWA, sync ou automação sem escopo e critérios de aceite;
- limpeza destrutiva apenas por estética técnica.

## Regras herdadas

1. `main` representa produção estável.
2. Alterações começam em `develop/v1.2`.
3. Preservar dados, URLs, localStorage, backups, contestId e IDs/namespaces dos mapas.
4. Manter modelo local-first.
5. Mudança visual exige auditoria desktop + tablet/iPad + celular.
6. Mudança de dados exige Data Safety.
7. Mudança de PWA/cache exige cold-offline e teste no deploy real.
8. Mudança de mapas exige a matriz real dos materiais.
9. ALTERAR → SALVAR → VALIDAR → REGRESSÃO → CONTINUAR.
10. Nenhuma feature entra apenas para preencher versão.

## Próxima etapa

Antes de qualquer implementação da V1.2:

- fazer auditoria do estado real pós-V1.1.0;
- listar necessidades observáveis;
- separar correção, dívida técnica e nova funcionalidade;
- definir prioridades e critérios de aceite;
- criar backlog V1.2;
- só então atualizar o contrato de produto para o novo ciclo, se necessário.
